    1. Update `store.ts`:
       - Add `is_active: boolean`, `address_city: string | null`, `address_street: string | null` to User interface
       - Add `updateUser: (user: User) => void` action to AuthState interface
       - Implement updateUser: `set({ user })`

    2. Create `features/auth/api/auth.ts`:
       - `loginApi(email, password)` — POST /auth/login, returns { token, user }
       - `registerApi(data: { name, email, password, password_confirmation, phone })` — POST /auth/register, returns { token, user }
       - `logoutApi()` — POST /auth/logout
       - `updateProfileApi(data)` — PUT /user, returns { data: User }
       - All use the existing `apiClient` from `shared/api/client`

    3. Create `shared/components/ProtectedRoute.tsx`:
       - Import `Navigate, Outlet` from `react-router` (NOT react-router-dom)
       - Check `useAuthStore((s) => s.user)` — if null, return `<Navigate to="/login" replace />`
       - Otherwise return `<Outlet />`

    4. Create `shared/components/AdminRoute.tsx`:
       - Same pattern as ProtectedRoute
       - If no user: redirect to /login
       - If user.role !== 'admin': redirect to /products
       - Otherwise: `<Outlet />`

    5. Create `LoginForm.tsx`:
       - Use react-hook-form + zodResolver pattern (same as Phase 2 admin forms)
       - Zod schema: email (string.email), password (string.min(8))
       - MUI TextField components for email and password
       - Submit button with loading state (isSubmitting)
       - Accept `onSubmit` prop for form submission
       - Display server error via an Alert component above the form (passed as `error` prop)

    6. Create `RegisterForm.tsx`:
       - Zod schema: name (string.min(2).max(255)), email (string.email), phone (string.min(8).max(20)), password (string.min(8)), password_confirmation (string.min(8))
       - Add `.refine()` to check password === password_confirmation with message "Passwords do not match" on path ['password_confirmation']
       - IMPORTANT: field name MUST be `password_confirmation` (not confirm_password) for Laravel's `confirmed` rule
       - MUI TextFields for all fields, submit button with loading state
       - Accept `onSubmit` and `error` props

    7. Create `LoginPage.tsx`:
       - Use MUI Tabs to switch between Login and Register
       - Container with max-width centered layout (Card or Paper)
       - On login success: call `loginApi`, then `useAuthStore.getState().setAuth(token, user)`, then navigate to /products (or /admin if admin role)
       - On register success: call `registerApi`, then `setAuth(token, user)`, navigate to /products
       - Use `useMutation` from TanStack Query for both login and register API calls
       - If user is already logged in (check store), redirect to /products immediately
       - i18n: use `useTranslation()` for all labels (add keys to FR/EN locale files: auth.login, auth.register, auth.email, auth.password, auth.phone, auth.name, auth.confirmPassword, auth.loginButton, auth.registerButton, auth.noAccount, auth.hasAccount)
