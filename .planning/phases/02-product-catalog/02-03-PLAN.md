  <action>
    **types.ts:** Define admin-specific types:
    - `AdminProduct`: extends catalog Product type but includes all-locale translations (not just current), is_active
    - `ProductFormData`: { sku, price (number, in centimes), stock_quantity, category_id, is_active, translations: { fr: { name, description, slug }, en: { name, description, slug } }, attributes: Record<string, string|number>, images: File[], delete_images: number[] }

    **api/products.ts:** TanStack Query hooks per Pattern 4 in RESEARCH.md:
    - `useAdminProducts(params?)` — `useQuery` queryKey `['admin', 'products']`, calls `apiClient.get('/admin/products', { params })`.
    - `useAdminProduct(id: number)` — `useQuery` queryKey `['admin', 'products', id]`, calls `apiClient.get('/admin/products/' + id)`.
    - `useCreateProduct()` — `useMutation` per research Pattern 4. Builds FormData: append sku, price, stock_quantity, category_id, is_active (as "1"/"0"), translations as nested `translations[fr][name]` etc., attributes as JSON string, images[] as file array. POST to `/admin/products`. **CRITICAL: Do NOT set Content-Type header on this request** — either omit it entirely or set to `multipart/form-data` (Axios will auto-add boundary). If the global apiClient has a default Content-Type of application/json, override it to undefined for this request: `{ headers: { 'Content-Type': undefined } }` so the browser generates the multipart boundary. onSuccess: invalidate `['admin', 'products']` and `['products']` queries.
    - `useUpdateProduct()` — `useMutation`, PATCH to `/admin/products/{id}` with FormData (same Content-Type handling). Also accepts `delete_images[]` to remove specific media.
    - `useDeleteProduct()` — `useMutation`, DELETE to `/admin/products/{id}`. onSuccess: invalidate queries.
    - `useDeleteProductImage()` — `useMutation`, DELETE to `/admin/products/{productId}/media/{mediaId}`. onSuccess: invalidate product query.

    **ImageUploader.tsx:** Props: `existingImages: ProductImage[]` (from edit mode), `onNewFiles: (files: File[]) => void`, `onDeleteImage: (mediaId: number) => void`.
    - Shows existing images as thumbnail previews with a delete (X) button on each. Clicking delete calls `onDeleteImage(id)`.
    - Has a file input (accept="image/jpeg,image/png,image/webp", multiple) with a styled MUI Button "Upload images" / "Telecharger des images".
    - New files show as preview using `URL.createObjectURL()`. Also have remove button (removes from local state only).
    - Calls `onNewFiles(files)` when files change.
    - Max 10 images total indicator.

    **ProductForm.tsx:** Props: `product?: AdminProduct` (undefined for create, populated for edit), `onSuccess: () => void`.
    Uses `react-hook-form` with `zodResolver`. Zod schema validates:
    - sku: z.string().min(1).max(50)
    - price: z.number().min(0) — input as MAD (e.g., 2499.00), convert to centimes (multiply by 100) on submit
    - stock_quantity: z.number().int().min(0)
    - category_id: z.number()
    - is_active: z.boolean()
    - translations.fr.name: z.string().min(1).max(255)
    - translations.fr.slug: z.string().min(1).max(255) — auto-generated from name (slugify)
    - translations.fr.description: z.string().optional()
    - translations.en.name, .slug, .description: same pattern
    - Attributes: structured fields for scooter specs — speed (string), battery (string), range_km (string), weight (string), motor_power (string). All optional.

    Form layout with MUI TextField, Select, Switch components:
    - Section 1: Basic info — SKU, Price (in MAD with label), Stock quantity, Category (Select from useAdminCategories — add a `useAdminCategories()` hook to `admin/api/categories.ts` in this task that calls GET `/admin/categories`; do NOT import from catalog feature to avoid cross-wave dependency), Active toggle (Switch)
    - Section 2: French translation — Name, Slug (auto-generated from name, editable), Description (multiline)
    - Section 3: English translation — same structure
    - Section 4: Specifications — speed, battery, range, weight, motor_power TextFields
    - Section 5: Images — ImageUploader component
    - Submit button: "Creer" / "Create" or "Mettre a jour" / "Update"

    On submit: calls `useCreateProduct()` or `useUpdateProduct()` mutation. Shows loading state on button. On success: call `onSuccess()` (navigate back). On error: show error message via MUI Alert.

    Auto-slug generation: When FR name changes, if slug hasn't been manually edited, auto-generate slug (lowercase, replace spaces with hyphens, remove special chars). Same for EN.

    **AdminProductsPage.tsx:** Route: `/admin/products`.
    - MUI DataTable or simple Table listing all products. Columns: Image (thumbnail), Name (FR), SKU, Price (formatted), Stock, Active (green/red chip), Actions.
    - Actions per row: Edit (link to `/admin/products/{id}/edit`), Delete (with confirmation dialog).
    - "Add product" button at top linking to `/admin/products/create`.
    - Toggle visibility: Click the Active chip to toggle is_active directly (PATCH request via useUpdateProduct with just is_active field).
    - Inline stock edit: Click stock number to show a small input, save on blur or enter (PATCH request).
    - Delete confirmation: MUI Dialog "Are you sure?" with product name.

    **AdminProductEditPage.tsx:** Route: `/admin/products/:id/edit` and `/admin/products/create`.
    - Uses `useParams()` to get `id`. If id exists, fetches product with `useAdminProduct(id)` and renders ProductForm with data. If no id (create route), renders empty ProductForm.
    - On success: navigate to `/admin/products` with success toast (use a simple MUI Snackbar or just navigate).

    **router.tsx:** Add admin routes inside the existing admin section (or create nested routes):
    - `{ path: '/admin/products', element: <AdminProductsPage /> }`
    - `{ path: '/admin/products/create', element: <AdminProductEditPage /> }`
    - `{ path: '/admin/products/:id/edit', element: <AdminProductEditPage /> }`
    - `{ path: '/admin/categories', element: <AdminCategoriesPage /> }` (placeholder import for Task 2)
    Keep existing routes. The admin routes should be nested under a layout that checks for admin auth (but auth is Phase 3 — for now, routes are accessible without guards).

    **Locale files:** Add admin strings (merge, don't replace):
    - FR: admin.products.title, admin.products.create, admin.products.edit, admin.products.delete, admin.products.confirmDelete, admin.products.sku, admin.products.price, admin.products.stock, admin.products.active, admin.products.inactive, admin.products.frenchName, admin.products.englishName, admin.products.description, admin.products.slug, admin.products.specifications, admin.products.images, admin.products.uploadImages, admin.products.save, admin.products.cancel
    - EN: Same keys with English values.
