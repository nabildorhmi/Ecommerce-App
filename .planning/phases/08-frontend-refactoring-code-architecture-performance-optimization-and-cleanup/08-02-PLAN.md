<task type="auto">
  <name>Task 2: Convert all deep relative imports to @/ aliases</name>
  <files>
    (all files listed in files_modified except tsconfig.app.json and vite.config.ts)
  </files>
  <action>
1. **Find all files with deep relative imports** (two or more `../` levels):
   ```bash
   grep -rn "from '\.\./\.\." src/ --include="*.ts" --include="*.tsx" | grep -v node_modules
   ```

2. **Conversion rules:**
   - `../../../shared/` becomes `@/shared/`
   - `../../shared/` becomes `@/shared/`
   - `../../../features/` becomes `@/features/`
   - `../../features/` becomes `@/features/`
   - `../../../app/` becomes `@/app/`
   - `../../app/` becomes `@/app/`
   - Single `../` imports WITHIN the same feature (e.g., `../components/X` from `pages/Y`) should be LEFT as relative — they are co-located and the relative import is clearer.
   - Imports crossing feature boundaries (e.g., from `features/admin/` to `features/auth/`) MUST use `@/features/auth/`.

3. **Key files to convert** (these have the deepest relative imports):
   - `src/app/router.tsx` — all page imports from `../features/*` become `@/features/*`
   - `src/features/*/pages/*.tsx` — imports from `../../../shared/` become `@/shared/`
   - `src/features/*/api/*.ts` — imports from `../../../shared/api/client` become `@/shared/api/client`
   - `src/shared/components/Navbar.tsx` — imports from `../../features/` become `@/features/`
   - `src/shared/components/Footer.tsx` — similar cross-feature imports
   - `src/main.tsx` — imports from `./app/`, `./shared/` become `@/app/`, `@/shared/`

4. **Preserve type-only imports:** If the original uses `import type { X }`, keep it as `import type { X } from '@/...'`.

5. **Do NOT convert:**
   - CSS imports (`import './index.css'`)
   - Imports within the same directory (`import { X } from './X'`)
   - Single-level relative imports within the same feature folder (`import { X } from '../types'`)
  </action>

    Run `grep -rn "from '\.\./\.\./\.\." src/` — should return zero results (no triple-dot imports remain).
    Run `npm run dev` and verify the app loads in browser without console errors.
  </verify>
  <done>
    All imports with 2+ levels of `../` are converted to `@/` aliases. TypeScript compilation passes. Production build succeeds. Dev server runs without import resolution errors.
  </done>
